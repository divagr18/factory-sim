# factorio-build

### Overview
- **Environment ID**: `factorio-build`
- **Short description**: Write a Python `def build(world):` program that builds a working iron smelting line in [factory-sim](https://github.com/divagr18/factory-sim), a C simulator of Factorio's early game. The program is scored by running it on a fixed subset of scenes.
- **Tags**: program-synthesis, code, simulation, single-turn, train, eval

### What it tests
The model gets the task, the program contract, the `world` API reference and
(optionally) notes on the game's mechanics. It has to write one program that
works on every scene of a subset: walk to an ore patch it can only partly see,
choose a layout that avoids walls and water, place a burner mining drill on
ore and a stone furnace under the drill's drop point, and fuel both. The
episode then runs a verification window, and a scene counts as solved when at
least 10 iron plates are machine-made in it.

The program sees only what a trained RL policy sees (the published
observation), and every action is one decision of the policy's action space.
It runs in a static sandbox: no imports, no dunder access, a short list of
builtins.

### Datasets
- **Source**: scenes are generated by `fsim.scenes.sample`, draw for draw the same as FactorioRL's generator.
- **Rows**: row *k* is scenes `seed + k*n_scenes` to `seed + (k+1)*n_scenes - 1` of the chosen split. Each row records its `subset_id` (`construct_smelting_line/<split>/<first>-<last>`) and the `(family, seed)` of each scene.
- **Splits**:
  - `train`: seeds 0 to 99,999, families `open_patch`, `offset_patch`, `varied_patch`, `cluttered_patch`.
  - `val`: seeds from 100,000 on, same families, never a train scene.
  - `holdout`: FactorioRL's frozen holdout stream (`obstructed_patch`, a family train and val never contain). The first 100 indices are the scenes FactorioRL's policies were measured on. **Evaluation only**: it is built only when you pass `split="holdout"`, and loading it logs a warning. Never use it as a training reward.

### Task
- **Type**: single-turn
- **Output format**: a brief plan, then one fenced ```` ```python ```` block containing the whole program. The last fenced block that defines `build` is used (and the text after `</think>`, when present).
- **Rubric**:

| Reward | Weight | Meaning |
| --- | --- | --- |
| `success_rate` | 1.0 | Fraction of the row's scenes where the line verifies. |
| `format` | 0.1 | +1 sandbox-valid program, −1 a program the sandbox refuses, 0 no program at all. |
| `refusal_penalty` | 0.0 (opt-in) | Minus the share of the program's intents the action space refused. |

So the seed program on 12 train scenes scores 1.0 + 0.1, a valid program that
builds nothing scores 0.1, a program with `import os` scores −0.1, and a reply
with no code block scores 0.

| Metric | Meaning |
| --- | --- |
| `success` | Per-scene success rate (what `success_rate` returns). |
| `success_macro` | Mean of the per-family rates. |
| `has_program`, `sandbox_valid` | 1/0. |
| `refusal_rate` | Refused intents / (decisions + refused intents). |
| `program_errors` | Scenes where the program raised. |
| `mean_decisions`, `mean_verified_output` | Per scene. |

`trace.info["factorio_build"]` records the first error and the program's
`normalized_hash` (blind to layout, comments and renaming), which is useful for
counting distinct programs in a group.

### Two entry points
verifiers 0.3.x ships two stacks, and this package supports both. Both score
through the same function, `factorio_build.core.score_completion`, so a
completion earns the same reward on either.

- **v1 (native)**: the exported `FactorioBuildTaskset`, run with `eval`. The package also exports `FactorioBuildHarness`, the built-in `null` chat harness, so an unpinned agent answers in plain chat rather than getting verifiers' default `bash` coding agent.
- **v0 (classic)**: `load_environment(**kwargs)` returns a `SingleTurnEnv` with a `Rubric`, which is what `vf-eval`, `prime eval run` and the `prime env init` template use.

`verifiers.v1` does not import on Windows (it needs `fcntl`). There, only the
v0 entry point is exported.

### Quickstart
Scoring needs factory-sim's compiled C extension (`fsim._fsim`). Build it from
a checkout first, then put the checkout on `PYTHONPATH` (see "Packaging for the
Hub" for why it is not a dependency yet):

```bash
git clone https://github.com/divagr18/factory-sim && cd factory-sim
uv sync && uv run python build.py            # compiles fsim/_fsim (needs a C compiler)
export PYTHONPATH=$PWD
uv pip install -e integrations/verifiers/factorio_build
```

v1 (Linux or macOS):

```bash
eval factorio-build -m <model> -n 8 -r 4 --env.taskset.n-scenes 16
eval factorio-build -m <model> --env.taskset.split val
eval factorio-build -m <model> --env.taskset.split holdout -n 6   # evaluation only
validate factorio-build --only-gold --taskset.num-examples 4      # no model: the seed program must solve a scene
```

v0:

```bash
vf-eval factorio-build -m <model> -n 8 -r 4 -a '{"n_scenes": 16, "split": "val"}'
```

### Taskset config
v1 fields are `--env.taskset.<name>` (dashes for underscores). `load_environment`
takes the same names as keyword arguments, with `task` for `sim_task` and the
task-level fields flattened.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `sim_task` (v0: `task`) | str | `construct_smelting_line` | The only task with a prompt and pinned sets. |
| `split` | `train` \| `val` \| `holdout` | `train` | `holdout` is evaluation only. |
| `n_scenes` | int, 1 to 64 | 16 | Scenes per row. |
| `num_examples` | int | 64 | Rows. |
| `seed` | int | 0 | First scene index of the split. |
| `game_notes` | bool | true | Include the mechanics notes (drop point, reach, fuel). |
| `task.workers` | int | 4 | Simulator processes per env worker. 0 runs in-process, with no process isolation. |
| `task.job_timeout_s` | float | 30 | Wall-clock limit per chunk. A hung worker is killed and replaced. |
| `task.decision_budget` | int | 600 | Decisions per scene. |
| v0 only: `format_weight`, `refusal_weight` | float | 0.1, 0.0 | Rubric weights. |

To turn on the refusal penalty in v1: `[env.taskset.task.rewards] refusal_penalty = { weight = 0.05 }`.

### Scoring cost and safety
A scene takes about 15 ms of CPU, so a 16-scene row takes about 0.25 s. The
sandbox is static, and it does not stop resource use (`while True: pass`
passes it). There are two guards. factory-sim's evaluator stops a program
after 2 s per episode (`evolve.evaluate.PROGRAM_TIME_LIMIT_S`), counting it as
a failure. Programs also run in `evolve.pool.EvalPool` workers: spawned
processes (spawn-safe on Windows) with a per-job timeout, where a worker that
hangs or dies is killed and replaced. Each env worker process keeps one pool,
shared by its rollouts. `workers=0` skips the pool, so it is for tests and
trusted code only.

### Packaging for the Hub
This package has **not** been pushed. It imports factory-sim's `fsim` and
`evolve` packages and the compiled `fsim._fsim` extension. factory-sim is now a
real package (setuptools + cffi, from 0.1.0): its sdist builds and passes a smoke
test on Windows and on Linux (gcc), with identical scores. What is left is where
the Hub resolves it from:

1. **Wheels on PyPI (the best option).** `.github/workflows/wheels.yml` builds manylinux, macOS and Windows wheels with cibuildwheel; publishing them to PyPI is the remaining step. Then add `"factory-sim>=0.1"` to `dependencies` here. Nothing is compiled at install time.
2. **A git dependency.** `"factory-sim @ git+https://github.com/divagr18/factory-sim@<tag>"`, as a PEP 508 URL in `dependencies`, not in `[tool.uv.sources]`, which never reaches the wheel's metadata. This works now, but it compiles C at install time, so every Hub sandbox or training node needs a C compiler and cffi's build dependencies.
3. **Vendoring the source.** Copy `csrc/`, `fsim/` and `evolve/` into this package and compile at install time. This forks the simulator, which the project avoids.

After step 1 or 2, also pin `factorio-build`'s version, run `validate
factorio-build --only-gold` on a Linux box, and push with `prime env push`
under the owner's chosen visibility. `factorio-tools` depends on this package,
so it has to be published after it.
