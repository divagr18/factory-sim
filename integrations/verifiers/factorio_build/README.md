# factorio-build

Requires `verifiers>=0.3.1` and `factory-sim>=0.1.2`, installed from PyPI with
prebuilt wheels.

The model writes one Python program, `def build(world):`, that builds a working
iron-smelting line in [factory-sim](https://github.com/divagr18/factory-sim), a
tick-exact simulator of Factorio's early game. The program runs on 16 scenes
it has never seen, and the reward is the fraction where the line makes at least
10 iron plates by machine during a verification minute. To get there it has to
walk to an ore patch it can only partly see, choose a layout that avoids walls
and water, place a burner drill on ore and a stone furnace under the drill's
drop point, and fuel both. The program sees only what a trained RL policy
sees, and every call it makes is one decision of that policy's action space.

## Taskset

- **Source:** scenes generated by `fsim.scenes.sample`, draw for draw identical
  to [FactorioGym](https://github.com/divagr18/FactorioGym)'s generator.
- **Rows:** each row is a block of `n_scenes` consecutive scenes (default 16)
  from one split.
- **Splits:**
  - `train`: seeds 0-99,999, four layout families.
  - `val`: seeds from 100,000 on, same families.
  - `holdout`: a family neither of the others contains (`obstructed_patch`).
    Its first 100 scenes are the frozen set FactorioGym's policies were
    measured on. Evaluation only: it is built only when asked for, and never
    as a training reward.
- **Reward:** `success_rate`, the fraction of the row's scenes solved, plus
  `format` at weight 0.1: +1 for a program the sandbox accepts, -1 for one it
  refuses, 0 for no program. An optional `refusal_penalty` is off by default.
- **Sandbox:** a static AST allowlist. No imports, no reflection, no attribute
  starting with `_`; at most 300 lines; 2 s per scene. The rules are stated in
  the prompt.
- **Scoring cost:** about 0.25 s of CPU per 16-scene row, in local worker
  processes. No GPU, container or network.
- **Validation:** `validate factorio-build --only-gold` runs a scripted seed
  program, which must solve its scenes.
- **Entry points:** the v1 taskset (`FactorioBuildTaskset`, Linux and macOS)
  and the v0 `load_environment`. Both score with the same function.

```bash
uv run eval factorio-build -m openai/gpt-6-luna -n 32 -r 1 --env.taskset.split val
uv run eval factorio-build -m openai/gpt-6-luna -n 6 --env.taskset.split holdout   # evaluation only
uv run validate factorio-build --only-gold --taskset.num-examples 4
```

## Baselines

One reply per row, zero-shot, game notes on, 16 scenes per row, and up to
32,000 completion tokens, reasoning included.

| Model | `val` scenes solved (32 rows) | `holdout` scenes solved (6 rows) | Programs accepted | Rows fully solved |
| --- | --- | --- | --- | --- |
| `gpt-6-luna` | 80.9% | 89.6% | 97% val, 100% holdout | 16/32 val, 2/6 holdout |

The `val` rows are subsets 0-31 at `seed=0`; the `holdout` rows are 0-5,
frozen indices 0-95. Six rows is a small sample. Almost every remaining
failure is a valid program whose plan fails on some scenes.

## Config

v1 fields are `--env.taskset.<name>`, with dashes for underscores.
`load_environment` takes the same names as keyword arguments, using `task` for
`sim_task` and flattening the task-level fields.

| Field | Default | Description |
| --- | --- | --- |
| `split` | `train` | `train`, `val` or `holdout` (evaluation only) |
| `n_scenes` | 16 | Scenes per row, 1 to 64 |
| `num_examples` | 64 | Rows |
| `seed` | 0 | First scene index of the split |
| `game_notes` | true | Include notes on mechanics: drop point, reach, fuel |
| `task.workers` | 4 | Simulator processes per env worker; 0 runs in-process, for trusted code only |
| `task.job_timeout_s` | 30 | Wall-clock limit per chunk of scenes; a hung worker is replaced |
| `task.decision_budget` | 600 | Decisions per scene |

To enable the refusal penalty in v1:
`[env.taskset.task.rewards] refusal_penalty = { weight = 0.05 }`.
