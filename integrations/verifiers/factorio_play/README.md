# factorio-play

factorio-play is an agentic environment built on Factorio, the
factory-building game. The model controls a player character through tool
calls, one action at a time: it looks around, walks, places machines, fuels
them, and sees the result of every action before choosing the next. When it
thinks the factory is ready it calls `finish`, the game runs a measurement
window, and the reward is what the factory actually produced.

This makes it a test of closed-loop behaviour. The model has to explore a map
it only partly sees, notice when an action is refused or doesn't do what it
expected, and recover, all within a fixed budget of decisions. The larger task
takes around 90 tool calls even when played well.

The maps run in [factory-sim](https://github.com/divagr18/factory-sim), a
tick-exact simulator of Factorio's early game that is checked against the real
game by [FactorioGym](https://github.com/divagr18/FactorioGym). Every action a tool
takes goes through the simulator's own API, so the rules and the budget are
exactly those of a trained policy.

If you want to train program synthesis instead, where the model writes one
Python program that builds the factory and is scored on maps it has never
seen, use the companion environment
[factorio-build](https://app.primeintellect.ai/dashboard/environments/divagr/factorio-build).
It uses the same tasks, maps and scoring.

It requires `verifiers>=0.3.1` and `factory-sim>=0.3.0`, both installed from
PyPI with prebuilt wheels. It runs on Linux and macOS; `verifiers.v1` does not
import on Windows.

## Tasks

There are two tasks. Choose one with `sim_task`.

| Task | The model has to | Reward | Decisions |
| --- | --- | --- | --- |
| `construct_smelting_line` (default) | walk to an iron patch, place a burner drill on ore and a stone furnace under the drill's drop point, and fuel both | 1 if at least 10 iron plates are made by machine during a verification minute | 600 |
| `belt_smelting` | walk between an iron patch, a coal patch and a wooden output chest, 20 to 40 tiles apart, and build a line of drills, furnaces, transport belts and burner inserters that carries plates into the chest | min(1, plates / 150), counting the iron plates that reach the chest during a ten-minute window in which the model cannot act; 1 exactly when the task succeeds | 2,500 |

`belt_smelting` starts with 4 burner drills, 4 stone furnaces, 40 belts, 10
burner inserters and 20 coal. Twenty coal runs a line for about 79 plates, so
the line also needs coal from the coal patch, mined by hand or by a drill.
Plates smelted from hand-mined ore do not count. Its tools are factory-sim's
`WorldV3`: public markers for the three sites, belts, inserters and chests,
`rotate`, hand-mining, `take_fuel` and belt lanes. The prompt carries the same
task text and measured mechanics that `factorio-build` shows a program writer.

## Taskset

- **Source:** scenes generated by `fsim.scenes.sample`, the same seed plan and
  splits as `factorio-build`. One task is one scene.
- **Splits:**
  - `train`: seeds 0-99,999, the training layout families (four for
    `construct_smelting_line`; `open`, `walled` and `split_patch` for
    `belt_smelting`).
  - `val`: seeds from 100,000 on, same families.
  - `holdout`: families neither of the others contains (`obstructed_patch`;
    `obstructed` and `far_chest`). Evaluation only: it is built only when
    asked for by name.
- **Tools, `construct_smelting_line`:** these cost no decision: `me`, `tile`,
  `inventory`, `ore_tiles(kind)`, `blocked_tiles`, `entities`, `patch`,
  `decisions_left` and `last_refused`. These spend decisions from a
  600-decision budget: `move(direction, stride)`, `place(item, x, y, facing)`,
  `give(row, item, amount)`, `take(row, item, amount)`, `mine(row)` and
  `wait(count)`. `finish()` ends the build phase. Unchanged from 0.1.1.
- **Tools, `belt_smelting`:** these cost no decision: `me`, `tile`,
  `inventory`, `ore_tiles(kind)`, `blocked_tiles`, `entities(kind)`,
  `marker(name)` (`iron`, `coal`, `output`), `belt_lanes(row)`, `opened`,
  `decisions_left` and `last_refused`. These spend decisions from a
  2,500-decision budget, exactly as `WorldV3` counts them:
  `move(direction, stride, count)`, `place(item, x, y, facing)` for drills,
  furnaces, belts, inserters and chests, `rotate(row, reverse)`,
  `give(row, item, amount)`, `take(row, item, amount)`,
  `take_fuel(row, amount)`, `mine(row)`, `mine_resource(x, y, amount, wait)`,
  `inspect(row)`, `wait(count)` and `finish()`. `inspect` opens a chest within
  reach and returns what it holds by item; `opened` reads it again for free
  until the character walks out of reach.
- **Entities** are named by their current `row` in `entities()`.
- **Reward:** `success` for `construct_smelting_line`, 1.0 if `finish` was
  called and the line verified. `score` for `belt_smelting`, factory-sim's own
  score for the task: min(1, plates delivered / 150). A rollout that never
  calls `finish` scores 0, because nothing was verified. Metrics: `finished`,
  `verified_output`, `decisions`, `refusals`, `tool_calls`, and `success` for
  `belt_smelting`.
- **Runtime:** each rollout gets its own MCP server process, simulator and
  scene. Every world action is one method call on factory-sim's `World` or
  `WorldV3`, so the budget, refusals and verification are exactly those of a
  program in `factorio-build`. The tests check this decision for decision.
- **Harness:** the default agent (`FactorioPlayHarness`) calls the model through
  the OpenAI **Responses API**, so reasoning models can think and call tools in
  the same turn. Its reasoning is carried from one turn to the next. A refused
  action returns the reason, and directions take `N/E/S/W` or words.

## Long episodes

`belt_smelting` is long. The reference builder, `fsim.belt_expert`, spends
about 275 to 370 decisions per scene, some 160 of them waiting for hand-mined
coal. So its tools fold runs of world actions into one call, each action still
counted by `WorldV3`:

- `move(direction, stride, count)` takes up to `count` strides and stops after
  one that does not move the character;
- `wait(count)` waits `count` decisions;
- `mine_resource(x, y, amount)` sends requests of 20, 5 and 1, each followed by
  the waits for its items, so 40 coal is one call of 162 decisions;
- `give`, `take` and `take_fuel` move any amount as transfers of 20, 5 and 1.

Replies are compact JSON, and `entities()` leaves out the fields that hold
nothing. The reference build, played through the tools on four `train` scenes,
takes 86 to 98 tool calls for 287 to 311 decisions. Its whole context, with
the system prompt and the tool schemas, is 12,000 to 13,300 tokens under
Qwen3.5's chat template, before any reasoning. A model that reads more, or
recovers from mistakes, uses more: set `max-turns` generously.

## Run it

```bash
uv run eval factorio-play -m openai/gpt-6-luna -n 8 --env.agent.max-turns 400
uv run eval factorio-play -m openai/gpt-6-luna -n 8 --env.taskset.sim-task belt_smelting --env.agent.max-turns 800
uv run eval factorio-play -m openai/gpt-6-luna -n 8 --env.taskset.split holdout --env.agent.max-turns 400   # evaluation only
```

## First run

`gpt-6-luna`, one `construct_smelting_line` `val` scene, reasoning on: the line
was built and verified (15 plates) in 12 model turns and 17 tool calls, with
no refused action. One episode shows the environment works end to end. It is
not a benchmark number.

## Config

| Field | Default | Description |
| --- | --- | --- |
| `sim_task` | `construct_smelting_line` | `construct_smelting_line` or `belt_smelting` |
| `split` | `train` | `train`, `val` or `holdout` (evaluation only) |
| `num_examples` | 64 | Scenes, one per task |
| `seed` | 0 | First scene index of the split |
| `game_notes` | true | Include notes on mechanics: drop point, reach, fuel, belts and inserters |
| `task.tools.decision_budget` | 600 | `construct_smelting_line`'s budget |
| `task.belt_tools.decision_budget` | 2,500 | `belt_smelting`'s budget |

## Changelog

- 2026-10-01 (0.3.0): `belt_smelting` follows FactorioGym 1.2.0, whose
  generator keeps scenes off the map's lake (the roughly 1% of scenes that
  touched water are redrawn; the rest are unchanged), and gains the `inspect`
  and `opened` tools. `construct_smelting_line` is unchanged. Requires
  factory-sim 0.3.0.
- 2026-09-28 (0.2.0): Adds `belt_smelting` (FactorioGym `belt_smelting`
  1.1.0) with factory-sim's `WorldV3` as tools, its train, val and holdout
  splits, and its score, min(1, plates / 150), as the reward. Its tools that
  take a count or an amount run several world actions per call, and their
  replies are compact JSON. `construct_smelting_line`'s tools, prompts and
  reward are unchanged. Fixes its action replies, which stopped carrying the
  refusal reason after an episode's twentieth action. Requires factory-sim 0.2.0.
- 2026-09-24 (0.1.1): The default harness uses the Responses API. Refused
  actions return their reason, and directions and facings accept words
  (`east`) as well as letters (`E`). Before this, every action a model phrased
  with a word was refused without explanation.
- 2026-09-24 (0.1.0): Initial release.
